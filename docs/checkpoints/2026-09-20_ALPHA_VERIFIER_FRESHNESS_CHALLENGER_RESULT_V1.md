# Verifier Freshness Challenger Result V1

Date: 2026-09-20 (Asia/Jakarta)  
Experiment: `TOOLING-042`  
Status: `PASS_FRESHNESS_MUTATIONS_DETECTED`

## Question and boundary

Does a draft versioned verifier-result contract distinguish a fresh verifier
result from a stale or unbound result, separately from whether the unchanged
authority packet itself validates?

The current verifier is not modified. The experiment uses synthetic wrapper
records around the unchanged outcome-blind authority packet. No protected
outcomes, providers, cloud state, canonical data, capture, telemetry, or
production state was accessed.

## Design

The draft contract requires:

- result schema version;
- current verifier code SHA-256;
- current packet SHA-256.

Five cases were tested: baseline, missing verifier hash, stale verifier hash,
stale packet hash, and stale result schema. The current packet verifier was run
on the unchanged packet in each case to isolate packet validity from result
freshness.

## Result

- Baseline draft freshness: PASS.
- All four stale/missing mutations: FAIL under the draft contract.
- Current packet validation: PASS in every case because the underlying packet
  was unchanged.
- Trial count: 5.

This confirms that packet validity alone cannot establish freshness of a
historical verifier result. The draft contract is not integrated.

## Limitations and disposition

`SUPPORTED_SCOPED`: the freshness gap is concretely bounded by synthetic
wrappers. This does not prove historical PASS artifacts were generated by the
claimed verifier, nor does it solve nested schema, value semantics, formula
correctness, or runtime access absence. Adoption requires independent review
and an explicit versioned-result contract.
