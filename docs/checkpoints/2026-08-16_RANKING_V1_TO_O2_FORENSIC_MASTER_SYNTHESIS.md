## Scope and boundary

This checkpoint synthesizes the completed forensic audits of Ranking V1, Ranking V2 (including A/B/C/D), Ranking V3 (A/B/C/D/E), and O2. It is documentation and adjudication only.

No model is fit. No historical outcome is rerun. No fresh-forward or protected outcome is accessed. No provider is called. No threshold, feature subset, target, model family, interaction, or hyperparameter is selected by looking again at consumed outcomes. No canonical model or forward counter is modified.

The purpose is to establish a clean scientific starting point for a future generation, not to rescue any historical model.

# 1. Executive conclusion

The dominant lesson from V1 through O2 is **not** that the project needs more features.

The dominant lesson is that the project progressively improved representation and research discipline while retaining two foundation-level assumptions that were never repaired:

1. the model population is conditioned on future barrier resolution (`TP_FIRST` versus `SL_FIRST`, excluding no-hit/unresolved states from the binary learning population); and
2. the signal is known only after session `t` closes while the research target is referenced to `Close_t`, which is not an executable post-signal entry price.

Those two assumptions limit the economic meaning of every V1/V2/V3/O2 ranking result, including the clean PIT-safe replays.

The current strongest clean historical benchmark remains Ranking V2 `HGB_XS_MARKET`. It should be retained as an incumbent **benchmark/control**, not treated as a final tradable model or as the template whose target and execution semantics must be inherited.

The post-V2 experiments still produced useful information-class lessons:

- causal Structure-Lite geometry showed real development-fold information but failed clean late confirmation;
- hard regime specialization failed and was methodologically confounded by data fragmentation/warmup loss;
- one nonlinear same-date LambdaMART ranking objective showed meaningful but unstable ordering and therefore leaves the ranking-native objective question open;
- O2 completed-session Open geometry remained incrementally informative conditional on V3-B after PIT correction, but failed as an exact standalone addition to Clean V2;
- therefore Structure and session geometry are candidate information blocks, not clean promoted architecture.

The next clean generation should **redesign target, executable entry clock, and date-centric evaluation before adding more alpha blocks**.

Master verdict:

`RETAIN_CLEAN_V2_AS_HISTORICAL_CONTEXTUAL_BENCHMARK; RESET_TARGET_EXECUTION_EVALUATION; CARRY_STRUCTURE_AND_SESSION_GEOMETRY_ONLY_AS_PREREGISTERED_CANDIDATE_INFORMATION_BLOCKS`

# 2. One-sentence interpretation of each generation

## V1 — disciplined first benchmark, wrong economic abstraction for final product

V1 proved the project could build a causal, fail-closed, chronological technical research model, but the locked holdout demonstrated transportability failure and the later forensic audit exposed target/population, execution, and objective mismatches that feature tuning cannot repair.

## V2 — representation repair, not proof of final successor

V2's durable contribution is the hybrid same-date cross-sectional + continuous market-context + stock-relative representation and stronger ranking shape, while clean replay shows incremental superiority over V1 is mixed and lower-tail robustness was overstated historically.

## V3 — useful hypothesis ladder, no clean successor

V3 tested recency, causal Structure-Lite, hard regime experts, PIT sector gating, and true grouped ranking; it generated important design lessons but the only old survivor, Structure-Lite, failed the corrected clean late gate, leaving Clean V2 as parent.

## O2 — conditional information survives, clean model lineage does not

O2 showed that completed-session Open geometry can contain historical information conditional on the Structure-Lite representation, but the exact Open3 block failed on Clean V2 and the full old O2 model cannot be promoted after its V3-B parent lost clean status.

# 3. What is now confirmed evidence

## 3.1 Scientific process / data governance

The following are strongly supported and should survive unchanged:

- chronological expanding validation rather than random split;
- purge/maturity gaps appropriate to the outcome horizon;
- fail-closed treatment of unknown listing/session/tradability/provenance state;
- exact row-identity and common-support comparisons for challengers;
- frozen candidate families before outcome access;
- no rescue/retune after a frozen gate failure;
- preserving unresolved/ambiguous data states instead of silently fabricating them;
- source/provenance hashes and reproducible artifact identity;
- independent review before promotion;
- willingness to retain the incumbent when a challenger fails.

These methodological assets are more durable than any one historical feature set.

## 3.2 Nonlinear capacity matters for the frozen technical state

The clean V2 A/B comparison uses the same ten XS stock-state ranks. The nonlinear HGB candidate materially exceeds the linear logistic candidate across median PR, q25 PR, ROC, and Q5-Q1. This is strong historical evidence that threshold effects/interactions matter for the frozen representation, even though the exact mechanism is not identified.

This supports retaining at least one nonlinear candidate in a future bounded model family. It does **not** make HGB mandatory.

## 3.3 Pure cross-sectional ranks are useful but insufficient

V2-B (`HGB_XS`) is a strong candidate and produces strong top-versus-bottom ordering, but it loses broad PR/ROC to the raw V1 HGB control. V2-C's hybrid context/relative package then improves median PR, ROC, and Q5-Q1 over B.

The durable representation lesson is therefore:

> retain both relative position and economically meaningful absolute/context state; do not assume percentile normalization alone solves drift or transportability.

## 3.4 Continuous market context is useful, but not uniformly stabilizing

Clean V2-C improves typical discrimination and Q5-Q1 over V2-B but has worse q25 PR. Thus market context changes ranking geometry beneficially on several metrics, but the gain is heterogeneous across folds.

The correct lesson is **contextualization**, not `market context solved regime shift`.

## 3.5 Ranking-aware learning remains a legitimate open question

V2-D modestly improves over V2-A, although objective effects are confounded with pair/date weighting and preprocessing. V3-E LambdaMART learns a materially different ranking and improves PR in three of four discovery folds but fails robustness/tail gates.

Therefore the project has evidence that group-aware/ranking objectives can materially alter useful ordering, but no clean evidence that the tested ranking-native architectures dominate contextual pointwise HGB.

The question remains open and deserves at most a small, fair, preregistered future comparison on the same information set and date weighting.

## 3.6 Causal support/resistance geometry is a real information hypothesis, not a proven successor

V3-B Structure-Lite adds genuinely new causal 60/120-session technical geometry. Its discovery benefit broadly survives the PIT correction, but the corrected V2F5 late comparison becomes materially negative and reverses the promotion verdict.

Thus Structure-Lite has **candidate information value** but demonstrated fragility. It should not be inherited wholesale or used as the parent of the next generation.

## 3.7 Completed-session Open geometry is more specific than generic gap/intraday return

O1's overnight gap / intraday return families failed their frozen survivor rule. O2's three same-session Open-geometry coordinates survived versus corrected V3-B, although with much smaller magnitude after PIT correction.

The useful lesson is that completed-session shape/location may matter conditionally. The exact three O2 columns are algebraically linked and should be treated as one geometry represented through multiple tree-friendly coordinates, not as three factors.

## 3.8 Open geometry is not established as standalone additive alpha

The exact clean V2 + O2 Open3 remediation fails: median paired PR uplift is essentially zero, q25 is negative, and only three of six folds are positive.

So `Open is alpha` is not supported. The strongest remaining hypothesis is conditional/contextual use of completed-session geometry.

# 4. Historical narratives that must be withdrawn or narrowed

The forensic audit requires the repository and future reasoning to stop using the following strong narratives.

## Withdraw: `V2 solved V1 regime instability`

Not established. Clean V2 has better median ROC/Q5-Q1 and a small median PR advantage, but its q25 PR is worse than the clean V1 control. The correct claim is that V2 is the best eligible clean V2 candidate and a stronger contextual ranking benchmark on several metrics.

## Withdraw: `V2 robustly dominates V1`

Not established. Counterfactually, if the V1 control had been champion-eligible under the frozen V2 tie-band/q25 rule, clean V1 would have won the lower-tail tie-break. This does not rewrite the historical V2 experiment, but it blocks the successor claim.

## Withdraw: `pairwise/ranking objective failed`

False. V2-D was a bounded linear pairwise experiment and modestly beat V2-A; V3-E was a nonlinear grouped ranker with mixed but nontrivial results. Ranking-native learning is unresolved.

## Withdraw: `V3-B is the final model`

False under clean lineage. Corrected PIT-safe replay rejects V3-B on the frozen late paired gate and retains V2.

## Withdraw: `sector-relative failed`

False. V3-D was correctly parked before model outcomes because PIT sector history was not defensible.

## Withdraw: `O2 is a clean champion`

False. O2's Open block retains conditional historical evidence, but the full model is orphaned by the rejected V3-B parent and exact Clean V2 + Open3 fails.

## Withdraw: `Open is useless`

Also false. Simple additive Open families fail, but Open is still highly relevant for a future executable-entry target and completed-session geometry may carry conditional information.

## Withdraw: `more data/features is the next bottleneck`

False. Foreign Flow direct alpha, Financial direct alpha, simple Open additions, V3 expansions, and other historical lanes already show that adding information classes to an economically misaligned target does not solve the foundation problem.

# 5. The common architectural flaw across all generations

Every V1/V2/V3/O2 model is evaluated inside essentially the same narrow target ontology:

- decision after session `t` close;
- label/reference at `Close_t`;
- H10 path;
- ATR14-derived TP/SL barriers;
- binary target only where path resolves as `TP_FIRST` or `SL_FIRST`;
- unresolved/no-hit observations excluded from the binary learning population.

This creates two separate but interacting problems.

## 5.1 Future-conditioned sample membership

Whether a row exists in the binary model population depends on what happens in the future. A quiet/no-opportunity row may disappear entirely rather than be represented as an economically meaningful outcome.

This changes the estimand from a daily opportunity-selection question toward something like:

`P(TP_FIRST | one barrier eventually resolves, eligibility, frozen H10 geometry)`.

Equal-date weighting alone cannot repair this because the population itself is future-conditioned.

## 5.2 Non-executable `Close_t` economic reference

The model sees completed session-t data and is therefore known after close. It cannot then enter retrospectively at `Close_t`.

An executable research question must distinguish:

1. information cutoff;
2. earliest admissible next action/entry price;
3. subsequent outcome clock.

With historical Open now available on roughly 95% of Clean V2 support, this is no longer merely a data-availability abstraction that has to be deferred.

## Consequence

No old PR-AUC / ROC / Q5-Q1 result, even on corrected PIT-safe data, is proof that the same ranking will survive when the target is redesigned around a feasible `t+1` execution state and full decision-time population.

Historical architecture lessons can transfer as hypotheses. Historical performance magnitudes cannot be assumed to transfer.

# 6. Learning objective and evaluation must become date-centric

The product decision is one cross-sectional event per trading date, not an undifferentiated bag of resolved security rows.

The old evaluator pools many row-level observations. Dates with more resolved/eligible rows carry more weight. Because row existence partly depends on future barrier resolution, date weighting can also become indirectly related to volatility/liquidity/regime.

The next clean contract should therefore make the date an explicit primary unit.

Required principles:

- decision-time population determined before future outcome is known;
- equal-date weighting or a separately justified date-weighting rule;
- date-level paired challenger-minus-incumbent diagnostics;
- top-N / top-decile / bottom-decile quality summarized by date as well as pooled rows;
- pooled PR/ROC retained only as complementary diagnostics;
- concentration/breadth checks across tickers, dates, liquidity strata and available PIT states;
- incumbent can win the promotion decision.

The exact metric family is not selected by this checkpoint.

# 8. Information blocks: retain, demote, or close

## Core contextual price/volume state — `RETAIN_AS_BASELINE_INFORMATION_CLASS`

Retain the concept of:

- relative stock state within the contemporaneous universe;
- continuous market state;
- stock-minus-market state;
- nonlinear interactions.

Do not automatically retain all exact V2 columns/lookbacks.

## Structure-Lite — `RETAIN_AS_HIGH-PRIORITY_CANDIDATE_BLOCK`

Reason:

- genuine causal new information;
- discovery value broadly survives PIT correction;
- clean late failure demonstrates fragility.

Future handling:

- redesign representation before any outcome run if economically justified;
- avoid post-hoc tuning of old 5/60/120/0.5ATR constants;
- improve corporate-action/split continuity assumptions before long-window geometry is trusted;
- separate event count from opportunity denominator where appropriate.

## Completed-session Open geometry — `RETAIN_AS_CONDITIONAL_CANDIDATE_BLOCK`

Reason:

- O1 generic gap/intraday families fail;
- O2 conditional incremental signal survives PIT correction against V3-B;
- exact Clean V2 + Open3 fails;
- likely interaction/reliability/shape information rather than standalone alpha.

Future handling:

- do not automatically carry exact three redundant coordinates;
- do not mine Structure × Open interaction rules from consumed history;
- if tested again, freeze a bounded geometry family before new-target outcomes.

## Hard regime specialists — `CLOSE_EXACT_ARCHITECTURE`

The tested NORMAL/STRESS split performs poorly and is confounded by warmup-row loss and independent-expert score scales. Preserve the lesson that hard sample fragmentation is inferior to the tested continuous-context baseline; do not rescue the exact experts.

## Recency weighting HL252/HL504 — `CLOSE_EXACT_ARCHITECTURE`

No robust benefit in the tested legacy development experiment. This does not prove drift is absent, but there is no reason to revive the exact exponential weighting rules.

## LambdaMART V3-E — `CLOSE_EXACT_CONFIG_KEEP_OBJECTIVE_QUESTION_OPEN`

Do not rerun/tune the consumed LambdaMART configuration. A fair future contextual ranking-vs-pointwise comparison remains scientifically legitimate after target/evaluation reset.

## Sector relative — `PARKED_NOT_FAILED`

Only revisit after point-in-time sector history has defensible coverage and effective/publication dates. Decide first whether sector exposure is desired alpha, risk control, or sidecar context.

## Foreign Flow direct additive alpha — `CLOSED_FOR_OLD_H10_CORE; RETAIN_STATE_HYPOTHESES`

The project's later accepted Foreign Flow V1/V2 direct-alpha tests do not justify appending the historical flow block to the old Clean V2 target. Preserve actor/supply/participation state as a separate information hypothesis, especially when paired with PIT supply/free-float context, but do not assume direct alpha.

## Financial PIT direct alpha — `NO_AUTOMATIC_CORE_INHERITANCE`

Existing direct-alpha experiments do not justify feature stuffing. Financial state remains an economically meaningful information class only under its own PIT/publication contract and a future preregistered target.

## Reliability / uncertainty — `RETAIN_AS_SIDECAR_CONCEPT`

Score-margin reliability has separate accepted evidence as a confidence/context sidecar. It should not be silently folded into alpha ranking or used to filter historical outcomes after the fact.

## Intraday price path — `DATA/SEMANTIC_RESEARCH_CONTINUES_SEPARATELY`

Intraday is genuinely new information and potentially valuable for execution/path ambiguity, but historical full-universe admission is not yet sufficient for unrestricted modeling. Do not block target redesign waiting for intraday.

# 9. Recommended sequence for the next clean generation

This section is a research-program recommendation, not authorization to execute it.

## Step 1 — freeze the economic decision problem before feature design

Define before outcomes:

- signal timestamp;
- earliest executable entry mechanism;
- eligible universe at decision time;
- whether abstention/no-trade is part of the decision;
- holding/outcome horizon;
- treatment of no-hit, ambiguous, suspension and missing-execution states;
- what quantity is actually ranked.

The project should not start with `which model/features?`.

It should start with:

> **What should a stock ranked #1 at close t mean economically at the moment the ranking can actually be acted on?**

## Step 2 — compare a small number of target families conceptually, then freeze one research contract

Candidate target classes that deserve specification review include:

### A. Executable next-session multi-state barrier target

Information through close `t`; entry/reference at the first defensible `t+1` execution state; subsequent TP/SL/no-hit/ambiguous outcomes all retained explicitly.

Pros:

- closest migration from the existing research ontology;
- preserves path/risk semantics;
- directly fixes Close_t pseudo-entry and future-conditioned binary population if no-hit remains explicit.

Risks:

- still inherits arbitrary barrier geometry unless economically justified;
- classification may still be an indirect proxy for ranking utility.

### B. Executable continuous forward utility / return target

Information through close `t`; executable entry at `t+1`; continuous future payoff or risk-adjusted path utility over a frozen horizon.

Pros:

- keeps magnitude and non-hit information;
- naturally rankable;
- avoids dropping quiet outcomes.

Risks:

- utility definition can become highly researcher-dependent;
- tail risk, censored paths, suspensions and corporate actions require careful semantics;
- naive forward return may reward high-beta/volatility rather than quality.

### C. Ordinal/multi-objective opportunity target

Represent adverse excursion, favorable excursion, terminal return, and/or barrier states without immediately collapsing them into one binary label.

Pros:

- preserves richer path information;
- can separate opportunity quality from confidence/risk.

Risks:

- more complex evaluator;
- easy to over-engineer after seeing outcomes.

This synthesis does **not** choose among A/B/C. A separate outcome-blind target-design specification should do so.

## Step 3 — freeze date-centric evaluation and successor governance

Before outcome fitting:

- incumbent Clean V2 benchmark/control must be able to win;
- same support where comparison semantics permit;
- explicit date-level primary metrics;
- complementary pooled discrimination;
- top-tail and breadth/concentration gates;
- worst-period / late-period non-inferiority rule;
- time-aware uncertainty/paired summaries where feasible;
- no candidate rescue after outcomes.

A new target means old Clean V2 scores are not necessarily a directly comparable incumbent under identical labels. The benchmark role may therefore require refitting the **V2 information architecture** under the new target rather than reusing the old fitted artifact. That refit would be a new preregistered development experiment, not a continuation of old V2 performance claims.

## Step 4 — establish a deliberately small core representation matrix

Only after target/evaluation are frozen, compare a small bounded family such as:

1. low-capacity sanity baseline;
2. contextual nonlinear core inspired by V2;
3. same information set with a fair date/group-aware objective if justified.

Do not immediately include Structure, Open, Foreign Flow, Financials, ownership, corporate actions and intraday all at once. First establish that the new target/evaluator produces a stable core benchmark.

## Step 5 — add information blocks one at a time under exact paired gates

Candidate order should be driven by scientific readiness, not historical excitement.

High-priority candidates:

- refined causal structure geometry;
- completed-session geometry / Open-derived state as a conditional block;
- reliability/confidence as sidecar rather than alpha unless separately justified.

Data-dependent later candidates:

- Foreign Flow state plus defensible supply/free-float normalization;
- PIT financial state;
- ownership/concentration state;
- corporate-action/event state;
- admitted historical intraday path.

Each block gets one frozen hypothesis and can fail without rescue.

## Step 6 — reserve genuinely fresh prospective confirmation

All information through 2026-07-31 and all historical model comparisons already inspected should be treated as development knowledge.

A newly specified target can still use historical data for development once frozen, but those historical results cannot serve as independent final confirmation merely because the label formula changed. Final confidence must come from a separately frozen future/prospective boundary that was not used to choose target, features, architecture, or gates.

Existing legacy O2 100-session forward machinery cannot automatically validate the new target lineage because it scores the old fitted O2/target architecture.

# 10. What should NOT happen next

Do not:

- run `Clean V2 + Structure + Open` now merely because the forensic audit suggests possible interaction;
- retune Structure-Lite constants on consumed historical outcomes;
- search many target barriers/horizons and choose the best result;
- revive O1 gap variants with minor normalization changes;
- rerun V3-C regimes with many thresholds;
- tune LambdaMART until it beats HGB;
- append Foreign Flow / Financial / Free Float / Corporate Actions / Intraday into one large model before the target reset;
- treat the existing O2 forward counter as validation of a newly designed clean generation;
- optimize execution/PnL, sizing, Kelly or portfolio rules before the signal survives the redesigned target and fresh prospective confirmation.

These actions would convert informative forensic findings into outcome-informed rescue/mining.

# 13. Final project state after forensic closure

The ranking lineage should now be remembered as:

```text
V1
  disciplined causal baseline
  -> locked holdout transportability failure
  -> exposes target/execution/objective questions

V2
  hybrid XS + market + relative contextual representation
  -> best current clean historical benchmark
  -> superiority over V1 mixed, not universal

V3
  recency: exact tested rules fail
  structure: informative but clean late promotion fails
  hard regime: fail / confounded
  sector: PIT blocked, never outcome-tested
  LambdaMART: materially different but unstable ranking
  -> no clean successor

O2
  completed-session Open geometry conditional signal survives PIT repair
  -> exact Clean V2 + Open3 fails
  -> old full O2 orphaned by V3-B parent
  -> retain geometry concept, no clean promotion
```

The most important next research move is therefore **not V4 feature engineering**.

It is an outcome-blind **next-generation target / execution / evaluator specification**.

Only after that specification is frozen should a new development experiment refit a small clean core under the new target and then evaluate candidate information blocks.
