## Expansion strategy

Target horizon: **1260 official IDX exchange sessions**, all ending on the same
latest session as the certified 504 baseline.

The target start date must be derived from an official IDX calendar, not from
weekdays or a five-calendar-year subtraction.

When a 504-session baseline is the exact trailing suffix of the 1260-session
window, the expansion adds exactly:

`1260 - 504 = 756 older official sessions`.

The normal network/data plan is therefore:

- preserve certified 504 artifacts read-only;
- build a sufficiently wide official calendar;
- select the exact trailing 1260 sessions;
- prove the certified 504 sessions are the exact target suffix;
- reuse valid Stock Summary cache pairs;
- fetch only uncached official Stock Summary sessions;
- extend PIT identity/delisting evidence backward;
- extend Yahoo raw prices only where additional ACTIVE sessions require them;
- use official IDX Stock Summary OHLC fallback only for primary-provider gaps;
- extend authoritative split/reverse-split verification to the exact 1260 range;
- rerun the ladder with a regression 504 horizon and the new 1260 horizon.

## New preflight contract

`src/idx_trade/history_preflight.py` was added on this branch.

It provides:

- `trailing_session_window(...)`: exact trailing official-session selection;
- `stock_summary_cache_coverage(...)`: cache-pair audit; a session is reusable
  only when both parquet and metadata JSON exist;
- `plan_history_expansion(...)`: validates that the certified baseline is the
  exact trailing suffix and computes the pure backward delta;
- `write_history_expansion_preflight(...)`: persists the exact plan and
  additional-session set before network work begins.

The preflight fails closed when:

- official calendar history is shorter than the requested horizon;
- the certified baseline is not an exact suffix of the target;
- baseline and target have different end/calendar semantics.

Partial Stock Summary cache entries are not trusted; they are scheduled for
refetch by the existing atomic cache path.

## Five-year risk classes to expect

The preflight does not assume these will occur, but 1260 may expose classes not
seen in 504:

- older delisted names absent from current identity surfaces;
- ticker/security reorganizations and mergers;
- older suspension/resumption market-scope evidence;
- larger Yahoo delisted-history gaps;
- additional official OHLC fallback requirements;
- corporate-action history at older boundaries;
- official source/schema availability changes;
- evidence-only historical securities that require type classification.

None of these may be solved by dropping common shares, treating row absence as
NO_TRADE, or weakening the data gate.
